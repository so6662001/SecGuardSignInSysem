## D1 · 设备接入总框架

```
读 docs/01 第 6 节。在 fv-device 建立设备接入总框架：
1. sys_device 设备档案：类型枚举(登记平板/车牌道闸/抓拍摄像头/人脸一体机/自助码立牌/地磅)、厂商、型号、连接方式、门岗/厂区归属、设备密钥(secret)、状态(在线/离线/故障)、最后心跳时间。管理接口：注册/编辑/删除/绑定门岗/重置密钥/在线列表。
2. 设备鉴权：/api/device/** 用 deviceId + 签名(HMAC，secret)校验的过滤器；防重放(时间戳+nonce)。
3. 心跳与巡检：POST /api/device/heartbeat；定时任务扫描超时未心跳→置离线→触发「设备离线」通知。
4. 设备事件总线：设备上报事件统一入 RabbitMQ，由各业务消费者处理（车牌→到厂匹配、人脸→核验、地磅→读数分发）。
5. 每类设备定义 SPI 接口 + Mock 实现 + 厂商实现骨架，application.yml 配置 provider 切换。
交付：设备管理接口 + 鉴权 + 心跳巡检 + 事件总线 + 各 SPI 骨架 + 测试。
```

## D2 · 车牌识别道闸 / 人脸一体机 / 抓拍摄像头

```
在 fv-device 实现（厂商以海康/大华为骨架，Mock 优先）：
1. 车牌识别 LprAdapter：
   - 接收：POST /api/device/lpr/event {deviceId,plate,imageUrl,time}；匹配 vehicle 与「待到厂/待放行」车辆单据；命中黑名单/受限则拒绝并告警；命中白名单/预约则可自动放行。
   - 下发：POST /api/device/gate/{gateId}/open（抬杆）；黑白名单下发。
2. 人脸一体机 FaceAdapter：
   - 下发人员：把访客/员工人脸注册到设备库（入场登记或邀请通过时）。
   - 接收：POST /api/device/face/event 识别回调 → 核验身份/测温 → 放行或拒绝。
3. 抓拍摄像头 CameraAdapter：抓图(ONVIF/ISAPI) → 存 MinIO → 返回 URL；用于入场存证、过磅车头/车厢抓拍。
Mock 实现：提供「模拟上报」测试接口，便于无硬件联调。绑定门岗后在 gate-config 显示设备在线态。
```

## D3 · 地磅（衡器）接入与磅房实时

```
在 fv-device + fv-steel 实现地磅接入（对应 weighbridge.html、steel-*.html）：
1. WeighbridgeAdapter：磅仪经 RS232/TCP → 串口服务器/边缘网关 → POST /api/device/weighbridge/reading {deviceId,weight,stable,time} 实时上报读数。
2. 稳定值判定与去抖；读数经 WebSocket 分发到「磅房工作站」当前地磅频道，前端大屏实时显示。
3. 记录皮重/毛重时校验：读数稳定、车牌与登记一致、与该车历史皮重偏差阈值内（防作弊），异常打标。
4. 过磅触发摄像头抓拍存证；净重/结算净重计算见 fv-steel B5。
Mock：提供模拟地磅推流接口（可设定重量序列）便于联调磅房与磅单闭环。
```

## D4 · OCR / 电子签

```
1. OcrAdapter（腾讯/阿里为骨架，Mock 优先）：身份证识别，checkin 证件识别 tab 调用，返回结构化(姓名/证件号/有效期)，敏感字段加密存储。
2. ESignAdapter（e签宝/法大大为骨架，Mock 优先）：checkin-secure 承诺书/保密协议——创建签署任务、返回签署链接或内嵌签名、回调更新签署状态、存证 PDF 存 MinIO 并可下载。
```

## D5 · 通知渠道厂商实现（短信/语音/微信/企微/钉钉）

```
在 fv-notify 补齐渠道厂商实现（Mock 优先，配置切换）：
1. Sms（阿里云/腾讯云）：模板短信、验证码、免登录审批短链短信；状态回执入 notify_log。
2. Voice（阿里云语音/云呼叫）：审批语音外呼「同意按1/拒绝按2」，按键回调 → 更新 visit_approval；Mock 提供模拟回调接口。
3. Wechat：公众号模板消息、小程序订阅消息（access_token 管理、模板配置）。
4. Wecom / Dingtalk：应用消息/机器人卡片，支持卡片内审批回调。
所有渠道接入 docs 第 7 节的编排与「超时自动升级」引擎；渠道优先级/开关来自租户 notify_channel_config（approval.html 配置）。
交付：各渠道实现 + 回执/回调 + 与升级引擎联通 + 测试（含 Mock 回调驱动的审批闭环）。
```

## D6 · 交易平台 / ERP 对接（钢铁专属）

```
在 fv-steel 实现交易平台「钢智汇」/ERP 对接适配器 TradePlatformAdapter（Mock 优先，REST + MQ 骨架）：
1. 单据核验带出：GET 提货用销售订单(客户/货物/应提/已提/剩余/结算状态)、送货用采购单(供应商/物料/采购量/已收/剩余/质检要求)；映射到 trade_order_ref。
2. 磅单/净重回写：车辆放行时把本车净重与磅单回写对应订单，更新已提/已收与剩余。
3. 承运商运力池入驻：POST /carriers/{id}/invite-trade 调用交易平台注册运力/发送入驻邀请。
4. 幂等与对账：单据同步幂等键、失败重试、对账任务。
Mock：内置若干示例订单/采购单（如 SO-260702-0391、PO-260702-0175），使 steel-checkin/steel-inbound 的「从交易平台核验」按钮可跑通带出与回写。
```

## D7 · 通知提醒场景总核对

```
核对并补齐全部提醒场景（逐一确认已接入通知引擎、模板齐全、渠道与升级正确）：
到访申请待被访人确认；审批同意/拒绝结果；访客入场/离场提醒被访人；超时滞留提醒(管理员+被访人)；当日自动离场；预约邀请发送/到访提醒；黑名单命中告警；试用到期/续费提醒；账单生成/欠费催缴；开通申请提醒运营；设备离线告警；磅单异常(超载/复磅差异)告警；承运商运力池入驻邀请。
产出「通知场景 × 渠道 × 模板 × 触发点」对照表，确保无遗漏。
```
