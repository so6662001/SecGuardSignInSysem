# 第三方接入切换说明

所有外部依赖均采用「适配器接口 + Mock 实现 + 厂商实现骨架」，通过配置切换；**默认全部 mock**，无需任何真实账号即可端到端运行。

## 配置项（`server/fv-bootstrap/src/main/resources/application.yml` 的 `fv:` 段，可用环境变量覆盖）

| 配置 | 默认 | 可选 | 说明 |
| --- | --- | --- | --- |
| `fv.channel.sms` | `mock` | `mock` / `aliyun` | 短信渠道；`aliyun` 启用 `AliyunSmsChannel` |
| `fv.channel.sms-config.*` | 空 | — | 阿里云短信 accessKey/sign/template |
| `fv.trade.provider` | `mock` | `mock` / `rest` | 交易平台对接；`rest` 启用 `RestTradePlatformAdapter` |
| `fv.trade.base-url` / `api-key` | — | — | 交易平台 REST 地址与密钥 |
| `fv.device.lpr-vendor` / `face-vendor` | `mock` | `mock`/`hik`/`dahua` | 设备厂商（骨架）|

## 切换原理
- 短信：`SmsChannel`(Mock) 用 `@ConditionalOnProperty(fv.channel.sms=mock, matchIfMissing=true)`；`AliyunSmsChannel` 用 `havingValue=aliyun`。二者 `code()="SMS"`，同一时刻仅一个生效，`NotifyService` 按 code 组装渠道 Map。
- 交易平台：`RestTradePlatformAdapter` 命名 `realTradePlatformAdapter` 并按 `fv.trade.provider=rest` 生效；`MockTradePlatformAdapter` 用 `@ConditionalOnMissingBean(name="realTradePlatformAdapter")` 兜底。
- 其它（人脸/车牌/OCR/电子签/微信）：`fv-device` 的 `DeviceAdapters` 提供接口与 Mock，接真实厂商时新增实现类并加 `@ConditionalOnProperty` 即可，无需改调用方。

## 接真实厂商的步骤（以阿里云短信为例）
1. `fv-notify/pom.xml` 引入 `com.aliyun:dysmsapi20170525`。
2. 在 `AliyunSmsChannel.send()` 内用 SDK 实际发送（TODO 已标注）。
3. 配置 `fv.channel.sms=aliyun` 与 `fv.channel.sms-config.*`。
4. 无需改动 `NotifyService` 与业务代码。
