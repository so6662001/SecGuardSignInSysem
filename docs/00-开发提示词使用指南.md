# 厂智访客 · Cursor AI 开发提示词使用指南

本目录是从高保真原型（`prototype/`，28 个页面）进入正式开发的一整套 **Cursor AI 开发提示词**。技术栈：**后端 Java（Spring Boot 3）+ 前端 Vue3**，多租户 SaaS，覆盖运营平台、PC 端、移动端、所有提醒、所有设备接入。

## 推荐开发顺序（里程碑）

1. **基座**：B0 → F0 →（可并行）M0、D1。
2. **平台运营 + 开通闭环**：B2 → F7、F8（申请开通→审核→租户创建可跑通）。
3. **系统域 + 通用访客核心**：B1 → B3 → B4 → F1~F5，配合 D5/D7 通知。
4. **移动端**：M1~M3（自助登记、被访人审批、员工端）。
5. **设备接入**：D2（车牌/人脸）、D3（地磅）、D4（OCR/电子签），先 Mock 后真机。
6. **钢铁专属版**：B5 → D6（交易平台对接）→ F6（提货/送货/磅房/承运商）。
7. **计费商业化**：B2 的订阅/账单/报价 → F8 的 pricing/quote → conversion 引流看板。
8. **联调测试部署**：B7 + D8，产出「功能对照清单」逐页核对无遗漏。

## 已备好的落地资产

- **数据库**：`server/db/migration/` 已含 V1~V6 Flyway 脚本（MySQL8/InnoDB/utf8mb4，多租户 `tenant_id`，含索引、注释与套餐/权限/平台超管/通知模板种子）。开发 B0 时把该目录拷入后端模块 `src/main/resources/db/migration/`，Flyway 自动建库。
- **接口契约**：`docs/api/openapi.yaml`（OpenAPI 3.0，93 端点，统一 `R<T>`/`PageResult`，含 bearer JWT 与设备签名两套安全方案）。可直接：① 导入 Apifox/Swagger 做联调 Mock；② 用 openapi-generator 生成后端 Controller 骨架与前端 axios/TS 类型。

## 使用方法（在 Cursor 中）

1. 打开本仓库，确认 `.cursor/rules/project.mdc` 生效（全局规则会自动带入上下文）。
2. 用 **Agent 模式**，按上面顺序，把某个提示词（如 B0）整段粘贴执行；执行前 Cursor 会读取全局规则与 `docs/01`。
3. 每个提示词内已包含「读哪些文件、做什么、交付什么、验收标准」。完成后自测通过再进行下一个。
4. 涉及第三方/硬件的部分先用 **Mock 实现**跑通，再按厂商骨架接真设备。
5. 每完成一个模块，运行测试 + 对照 `prototype/` 对应页面核对功能是否齐全。

## 关键约束（务必保持）

- **功能齐全、逻辑不缺失**：以 `prototype/` 的 28 个页面为准，每页对应的后端接口、前端页面、移动端（如有）、通知与设备联动都要落地。
- **多租户隔离**：所有租户业务表带 `tenant_id`，运营域不参与租户过滤；专属域名路由到对应租户。
- **两条腿**：通用版对所有租户可用；钢铁专属版按订阅能力开关启用（车辆/磅单/交易平台）。
- **可运行**：Mock 化第三方，本地一键起服务即可端到端跑通主流程。
- **不交付空壳**：不允许 TODO 占位式空方法；确需分期须在 PR 说明列出。
